# NINApp PRD

## 1. 概要

- プロダクト名: `NINApp`
- 種別: モダンな服と雑貨を扱うECサイト
- 現在の実装形態: TypeScript + React + Vite によるフロントエンド中心のモックEC
- 目的: ブランドの世界観、商品導線、会員設定、カート体験を一貫したUIで検証できる状態を作る

## 2. プロダクト背景

NINApp は、オフホワイトを基調に、パステルカラーとグリーンを差し色として取り入れた、服と生活雑貨のECサイトである。  
単に商品を並べるだけでなく、服と部屋の空気感を同じ感覚で選べることを価値に置く。

ブランドの中核は以下の通り。

- きれいめだが、力みすぎない
- 無機質すぎず、生活にやわらかさが残る
- 20代から30代の感度の高い女性に強く刺さる
- ただしメンズでも違和感なく見られるニュートラルさを保つ

## 3. ターゲット

### コアターゲット

- 20代から30代の、おしゃれ感度が高い女性
- 会社ではカジュアル寄りの服装をしている
- 生活は肩肘張りすぎず、自然体で整えたい
- 部屋が冷たく無機質になりすぎるのは避けたい
- 服だけでなく、暮らしの小物や空間づくりも含めて自分らしさを整えたい

### セカンダリーターゲット

- レディース中心の世界観は好みつつ、甘すぎる空気感は避けたい男性
- パートナーや同居人と一緒に見ても違和感のないEC体験を求める人

## 4. 提供価値

- 通勤と休日の境目を自然につなぐ服を探せる
- 服と雑貨を同じブランドトーンでまとめて選べる
- オフホワイト中心の穏やかな世界観の中で、商品が見やすい
- パステルとグリーンを使って、やさしく洗練された印象を受ける
- レディース中心でも、メンズや共有生活にも広げやすいニュートラルさがある

## 5. ブランド / デザイン方針

### 5.1 トーン

- 清潔感
- やわらかさ
- モダン
- 肩肘張らない上質さ
- 男女問わずなじむ中性的バランス

### 5.2 ビジュアル方針

- ベースカラーはオフホワイト
- パステルピンク、ペールブルー、やわらかいグリーンを差し色に使う
- グリーンは「空間に植物や落ち着きを入れる」印象づけとして機能させる
- 強い黒ベースではなく、深いグリーンや柔らかなダークトーンで締める
- ガラス感、淡いグラデーション、柔らかい影で軽やかさを出す

### 5.3 コピー方針

- 強すぎるラグジュアリー表現は避ける
- 生活と感性に寄り添う語り口にする
- 服と部屋、両方の気分を整えることを言語化する
- 女性向けに寄りすぎた文言を避け、共有しやすい空気感を保つ

## 7. 情報設計

### Home

- ブランドの世界観を最初に伝える
- 服と雑貨を一緒に選べるサイトであることを明確にする
- 人気商品へ自然につなぐ

### Product List

- 服と雑貨を同じトーンで一覧比較できる
- 商品画像、商品名、説明、価格が視線順に整理されている

### Product Detail

- 商品単体の魅力に加え、生活や空間への馴染み方も訴求する
- カート追加までの導線を短くする

### Cart

- 選択した商品の確認と数量調整を簡潔に行える
- 小計がすぐに把握できる

### Login / Register

- フロントエンド検証用の会員導線を用意する
- 認証機能そのものより、導線とUI確認を優先する

### Settings

- 購入や配送に必要な会員情報をまとめて編集できる
- 配送先は現実的な入力項目に分割する
- エラー表示はフィールド単位で一貫させる

## 8. Settings 仕様

### 8.1 支払い方法

- 登録カード
- カード名義

### 8.2 認証情報

- メールアドレス
- 新しいパスワード

### 8.3 配送先情報

- 姓
- 名
- ミドルネーム
- セイ
- メイ
- ミドルネーム(カナ)
- 郵便番号
- 都道府県
- 市区町村
- 番地
- マンション名・建物名
- 電話番号

### 8.4 バリデーション要件

- 必須項目はラベル横に赤字の `※` を表示する
- メールアドレスは形式チェックを行う
- パスワードは8文字以上
- 郵便番号は `123-4567` を許容する形式
- 電話番号は数値・ハイフン等を含む一般的な形式を許容する
- カナ項目はカタカナであることを前提にチェックする
- エラー表示はフィールド直下に表示する
- settings 画面ではブラウザ標準のフォーム検証ではなく、独自バリデーションを使う

## 10. 技術方針

### 10.1 アーキテクチャ

- Feature-Sliced + Container / Presentational 分離
- `app`: 画面接続と全体制御
- `features`: 状態、モデル、バリデーション、処理
- `pages`: 画面単位の束ね
- `views/components`: 表示中心

### 10.2 データ取得

- 商品とデモユーザは `public/mock` 配下のJSONを取得する
- 現時点ではフロントエンドのUI検証が中心

## 11. 非機能要件

- デスクトップとモバイルでレイアウトが破綻しない
- 視認性を保ちながらブランドらしさを出す
- フォーム入力時にエラー原因が明確である
- 商品導線が過度に複雑にならない
- 将来的なAPI接続に備えて責務分離を保つ

## 12. 成功指標の仮置き

- ブランドの世界観がトップページだけで理解できる
- 人気商品から商品詳細、カートまで迷わず移動できる
- settings の入力エラーがユーザに理解されやすい
- レディース中心の見え方を持ちながら、メンズでも違和感の少ない印象を維持できる
